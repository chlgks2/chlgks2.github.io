LoL 승률 예측 시스템

Op.gg 를 크롤링해 데이터를 모으고 머신러닝으로 승률을 예측한 2주 과제입니다. 데이터 수집 → 전처리 → 학습까지를 처음부터 끝까지 직접 만들어 본 첫 프로젝트이고, 여기서 겪은 전처리의 무게가 이후 데이터를 직접 설계하는 작업의 출발점이 됐습니다.

무엇을 했나

리그오브레전드 전적 사이트 Op.gg 를 크롤링해 유저의 게임 데이터를 수집하고, 머신러닝 분류 모델로 승률을 예측했습니다.

가장 많은 시간을 쓴 곳은 모델이 아니었습니다

처음에는 "모델을 잘 고르면 되겠지"라고 생각했습니다. 실제로는 크롤링한 원본을 쓸 수 있는 형태로 만드는 데 대부분의 시간이 들어갔습니다.

  • 페이지 구조가 유저마다 달라 누락되는 필드가 생김
  • 수집 단위가 달라 정규화 기준을 직접 정해야 함
  • 어떤 값을 피처로 쓸지 판단하는 것 자체가 작업
모델을 돌리기 전에 데이터가 준비되어 있어야 한다는 것을, 머리로가 아니라 일정으로 체감한 프로젝트입니다.

이후 작업에 남긴 것

여기서 겪은 전처리의 무게가 이후 데이터를 직접 설계하는 작업의 출발점이 됐습니다.

이 프로젝트이후
크롤링 원본을 쓸 수 있는 형태로 만드는 데 대부분의 시간 엄마 이게뭐야 — 데이터를 직접 수집·라벨링(94클래스 5,576장)
공개 데이터의 한계를 처음 경험 Emour — 공개 말뭉치를 버리고 학습 데이터 3,648건을 직접 구축
"모델보다 데이터"라는 감각의 시작 Dream Shaper — 화자별 결과 차이가 전부 확보한 데이터 양에서 나온 것을 확인
Emour에서 공개 말뭉치를 버리고 데이터를 직접 만들기로 한 판단은, "모델보다 데이터가 결과를 가른다"는 것을 이 과제에서 처음 체감했기 때문입니다.

한계

저장소와 발표 이후 산출물이 남아 있지 않습니다. 정확도·피처 목록·사용한 분류 모델 같은 세부는 확인할 방법이 없어 확인되지 않는 성능 수치는 적지 않았습니다.

2주짜리 교육 과정 과제였고, 이 포트폴리오에서의 의미는 성능이 아니라 순서입니다 — 데이터 파이프라인 전 구간을 처음 경험한 프로젝트라는 점에서 남겨두었습니다.
