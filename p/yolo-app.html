아이를 위한 실시간 객체 탐지 앱 개발

아이가 "엄마 이게 뭐야?"라고 묻는 상황을 앱이 대신 받아주는 것이 출발점입니다.

기획 의도는 "아이의 호기심을 해결해 주면서, 부모가 자녀의 관심사를 손쉽게 알 수 있는 서비스" 였고, 세 가지 기능으로 나눴습니다.

기능내용
① 뭐든 물어봐물건을 비추면 탐지 → GPT 설명 생성 → gTTS 음성으로 읽어줌
② 아이의 관심사 알림탐지 기록을 쌓아 날짜별 차트 + 부모 이메일 리포트
③ 단어 학습손가락 제스처로 조작하는 단어 맞추기 게임

담당 범위

AI 개발자 5명 팀에서 데이터 수집 · 이미지 라벨링 · YOLOv8 커스텀 학습 · 손가락 제스처 인식 · 음성 출력 · Flask 백엔드를 담당했습니다. 발주처는 한국전파진흥협회입니다.

모델 학습에서 끝내지 않고 서비스에 연결해봐야 실제 문제가 보인다는 것을 처음 체감한 프로젝트입니다. 노트북에서 잘 돌던 추론이 실시간 요청에서는 다르게 동작하고, 학습 시 전처리와 서빙 시 전처리를 일치시켜야 한다는 것도 이때 알았습니다. 이 감각은 이후 Emour에서 AI 서버와의 계약(스키마·라벨)을 고정하는 설계로 이어졌습니다.

클래스 불균형이 발목을 잡았습니다

데이터를 직접 만들었습니다

집 안 물건 중심으로 94개 클래스, 5,576장을 직접 수집하고 라벨링했습니다. 의자·마우스·이어폰 같은 일반 사물부터 프라이팬·가스레인지·고무장갑·샤워타올처럼 공개 데이터셋에 잘 없는 생활용품까지 포함했고, 아이 대상 서비스라 동물 인형 클래스도 따로 넣었습니다.

94개 중 4개는 인물 클래스이고, 나머지 90개가 사물입니다.

문제 발견

사전학습된 YOLOv8이 이미 아는 객체 외에 서비스에 필요한 물건을 커스텀 클래스로 추가해야 했습니다. 학습 결과를 확인하다가 커스텀 클래스의 탐지율이 유독 낮다는 것을 발견했습니다. 원인을 따라가 보니 학습 데이터의 구성 자체가 기울어져 있었습니다.

  • 기존 사전학습 클래스 — 대규모 공개 데이터셋으로 이미 충분한 샘플
  • 새로 추가한 커스텀 클래스 — 직접 수집·라벨링한 소량의 이미지
클래스 간 샘플 수 격차가 크면 모델은 다수 클래스로 예측을 몰아버리는 것이 손실을 줄이는 데 유리하다고 학습합니다. 손실 함수 입장에서는 소수 클래스를 포기하는 것이 합리적 선택입니다.
커스텀 클래스를 아예 예측하지 않는 방향으로 수렴하는 것이 이 문제의 본질이었습니다. 모델을 더 크게 바꾸거나 오래 돌려도 해결되지 않습니다 — 학습 신호 자체가 그 방향을 가리키기 때문입니다.

세 가지 모두 데이터를 손대서 해결했습니다

#조치내용
1데이터 증강Rotation · Cutout 등으로 소수 클래스를 약 3배 확보
2클래스별 샘플 수 조정데이터셋 구성 단계에서 클래스 간 비율 격차를 줄임
3오라벨 수정학습 데이터를 다시 훑어 잘못 라벨링된 것을 찾아 고침

3번이 의외로 효과가 컸습니다. 5,576장을 사람이 나눠 라벨링하다 보니 기준이 흔들린 구간이 있었고, 모델이 못 맞히는 클래스를 따라가 보면 데이터 쪽에 원인이 있는 경우가 많았습니다.

"모델이 틀렸다"보다 "라벨이 틀렸다"를 먼저 의심하게 된 계기입니다.

좋은 특징을 고르니 모델이 단순해졌습니다

글을 모르는 아이가 화면을 만지지 않고 조작할 수 있어야 했습니다. MediaPipe의 손 랜드마크를 그대로 쓰지 않고, 각도 특징을 뽑아 KNN으로 분류했습니다.

왜 좌표가 아니라 각도인가 — 랜드마크 좌표를 그대로 쓰면 손이 카메라에 가까울 때와 멀 때, 화면 어디에 있느냐에 따라 값이 전부 달라집니다. 뼈대 벡터를 정규화하고 그 사이 각도만 남기면 손의 크기·위치·거리와 무관한 특징이 됩니다. 이 표현 위에서는 KNN 하나로 충분했습니다.

화면에는 아이용 단어 30개 중 5개를 무작위로 배치하고, 정답 단어의 그림을 우측 상단에 보여줍니다. 한글은 OpenCV가 그리지 못해 PIL로 렌더링한 뒤 배열로 되돌리는 방식으로 처리했고, 캐릭터 오버레이는 알파 채널을 직접 블렌딩했습니다.

한계와 배운 점

이 프로젝트의 가장 아쉬운 점은 지표를 남기지 않은 것입니다. 개선 여부를 육안 확인과 탐지 성공 여부로만 판단했고, 클래스별 precision/recall과 mAP를 before/after로 기록해두지 않았습니다.
한계내용
성능 지표 부재개선을 수치로 증명할 수 없습니다. 저장소에 runs/ 로그도 남아 있지 않습니다
탐지 결과 이미지 경로가 절대경로 predict(save=True) 가 만든 폴더를 파일시스템에서 직접 찾아 읽습니다. 예측 결과를 메모리에서 바로 인코딩하는 편이 맞습니다
게임 상태가 지역 변수동시 접속 시 세션 분리가 되지 않습니다
웹캠을 서버가 직접 연다cv2.VideoCapture(0) 이 서버 측 카메라를 잡으므로 로컬 실행 전용입니다
text-davinci-003 단종현재는 사용할 수 없어 최신 모델로 교체가 필요합니다

발표 당시 정리한 상용화 과제

  1. 데이터 불균형 — 기존 YOLOv8 클래스와 새로 추가한 커스텀 클래스 사이의 격차
  2. TTS 개선 — 기계음 대신 아이가 좋아하는 캐릭터 목소리, 다국어 지원
  3. 앱 출시 — 언어 선택(한국어/English/日本語/中文/Français) · 음성 선택

배운 점

  • 데이터 문제는 모델을 바꿔서 해결되지 않습니다. 탐지율이 낮은 원인이 모델이 아니라 데이터 구성에 있다는 것을 확인한 첫 경험이었습니다. 증강·비율 조정·오라벨 수정 셋 다 데이터 쪽 조치였습니다
  • 개선을 주장하려면 지표가 먼저 있어야 합니다. 이 프로젝트에 지표가 없었던 것이 이후 Emour에서 평가 기준을 먼저 정하고 데이터 누수까지 차단하는 방식으로 이어졌습니다
  • 좋은 특징 설계는 모델을 단순하게 만듭니다. 손 제스처는 좌표를 각도로 바꾼 것만으로 KNN 하나면 충분했습니다
